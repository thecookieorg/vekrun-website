Plan mode asks an agent to investigate your project and propose a plan: requirements, the proposed approach, milestones, tasks with their dependencies, risks and acceptance criteria.

## Review and approve

Read the plan, then approve it or ask for another revision. Revisions are kept, so you can compare a new plan with an earlier one.

:::note[Planned]
Editing a plan in place before approving it is planned; today you ask for a new revision instead. See the [roadmap](/roadmap/).
:::

## From plan to tasks

An approved plan becomes Factory tasks. Each task knows which part of the plan it implements, so a delivered change can be traced back to what you approved.

A ticket from the [Board](/docs/board/start-work/) can start a plan with the ticket attached, so the chain runs ticket, plan, tasks, verified change.

## Keep it light

Planning is optional. For a small change, work with a single agent in Build mode and skip the plan.
